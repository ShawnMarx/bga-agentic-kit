# Reading the table

## The state probe (run in the game frame)

```js
() => {
    const g = window.gameui && window.gameui.gamedatas;
    const st = (g && g.gamestate) ? g.gamestate : {};
    const btns = Array.from(document.querySelectorAll(
        '#generalactions .bgabutton, #generalactions button, .action-button'))
        .map(b => ({text: (b.innerText || '').trim(),
                    color: (b.className.match(/bgabutton_(\w+)/) || [])[1]}))
        .filter(b => b.text);
    const title = (document.querySelector('#pagemaintitletext') || {}).innerText || '';
    return {state: st.name, id: st.id, active: st.active_player, title: title.trim(), buttons: btns};
}
```

`gamestate.name` is the state class name on the modern skeleton and is what a loop branches on.
`GAME`-type states have no active player — wait them out.

## Where things live

| what | where |
|---|---|
| framework Gamegui, `gamedatas`, `gamestate` | `window.gameui` (in the game iframe) |
| **your** client instance, its live fields and helpers | `window.g_sitecore.GameModule` |
| current player | `GameModule.bga.players.getCurrentPlayerId()`, `.isCurrentPlayerActive()`, `.isPlayerActive(id)` — on `bga.players`, not `bga` |
| status bar title / action buttons | `#pagemaintitletext`, `#generalactions` |
| game log | `#logs` |

`gamedatas` is the page-load snapshot — stale mid-phase by construction, and it carries raw DB column
names where your client may have renamed them. Neither is a bug. Read live values off `GameModule`.

**Find things by reading state, not CSS classes.** A "selectable" class can stay on an element that is
already done, so `querySelector` keeps returning the same finished item and the run stalls. Ask the
client which items are still live, then click that one.

## Audit button colour, not just presence

A red forward button is invisible to a label-only probe. Read `bgabutton_blue` / `_gray` / `_red`
alongside the text. A confirm that only renders when some flag is set cannot be found by reading the
source's button list — only a driven table shows it.

## Modals

If your client follows BGA's guideline of status-bar confirmations instead of dialogs, a dialog on
screen during a drive is a bug to report, not something to click through.

## Measuring CSS on the table

- **Zoom wrappers lie to `getBoundingClientRect()`.** BGA may put a `zoom` on a wrapper around your
  board (*(Reckoners)* `zoom: 1.4`, so a measured 35px icon was a 25px rule). Read
  `getComputedStyle(el).width` and walk the ancestors for `zoom` before concluding a rule missed.
  Elements outside the wrapper measure 1:1, which makes the discrepancy easy to misread.
- **Measure, don't assume.** A selector that is valid but matches nothing passes every linter and the
  build. A probe returning `null` for the element you styled is what catches it.

## The action lock ("a valid click does nothing")

Symptom: valid-looking clicks change nothing, across different routes to the same action; no banner,
no state change. Cause: an earlier request is still pending and every later click is refused. **The
tell is in `#logs`**: *"Please wait, an action is already in progress"* (`Generated by: checkAction/…`).
Fix: reload the tab (re-confirm the seat). Nothing is lost. Check the log for this before concluding
the client is broken.

## The main-site table record

The game list's "your turn" flag and Progression come from the **main site's table record**, not your
game: `table_infos` embedded in Studio pages, or `/table/table/tableinfos.html?id=<table>` with header
`X-Request-Token: bgaConfig.requestToken`. Your `updateGameProgression` can be 20 while the record
says 0.

- Only **turn-based** speed gives a meaningful `myturn`; "No time limit" reads null.
- A clock-less (Training) table's record is written once at start, so **a solo table never shows a
  stored Progression** whatever the game does — a known platform limitation, not your bug.

## Replays and bug reports

These live on the **main site** and need `bga.sh login_main.py`. Stepping a replay: `&step=N` in the
archive URL is ignored and a scripted click on "Go to move" is ignored — call
`window.gameui.archiveGoToMove(N)` in the game frame and **poll** until the log shows the move (it
replays from the start).

## Phone layouts

Emulate the device, not just the viewport, so touch, pixel ratio and user agent match:

```python
dev = dict(p.devices["iPhone 15 Pro Max"]); dev.pop("default_browser_type")
ctx = p.chromium.launch_persistent_context(user_data_dir=str(S.profile_dir()), headless=True, **dev)
```

It renders at 430 CSS px (below BGA's 480 interface minimum). The cookie banner covers the lower half —
remove the `position: fixed` element containing "cookies" before an element screenshot.
